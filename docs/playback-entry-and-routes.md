# TV and mobile playback changes

Online entry verifies the authenticated account, device binding and paid screen admission before enabling a network stream. TV splash waits for admission and initial local profile/catalog preparation. TV authentication records the Firebase-authenticated owner before admission.

Mobile offline entry opens the account's local library after local profiles/catalog are ready, without waiting for Firestore or a remote catalog. Downloaded playback requires the original verified membership, device and expiry, independently of concurrent online screen slots. Existing installations can recover that proof from a committed Firestore subscription cache; Mobile/Basic also require a committed device binding matching this device. Pending writes cannot grant membership. Confirmed revocations/sign-out leave installation-local markers so older cached data cannot resurrect access. A library with no recoverable entitlement still opens for inspection and deletion, while playback asks for verification and saved subscription details remain intact. New streaming remains disabled until fresh membership/device verification and screen admission succeed.

The admitted session belongs to the current account and this app process. Player entry, source resolution, episode transitions and Retry use local entitlement and admission state. They do not start another Firestore membership transaction. Navigation does not release and immediately reacquire a screen slot. Sign-out and app-session disposal release the claim.

The online entry claim starts a background refresh after 20 seconds. A temporary connection error preserves the already verified membership and admitted session. Offline mobile entry avoids remote membership requests while disconnected and refreshes admission in the background after reconnecting, with bounded retries. Explicit device/authorization denial, membership revocation, account changes and the existing subscription expiry rules still stop unauthorized playback. A full concurrent-screen allocation blocks new online streaming without revoking otherwise valid downloaded playback. A server-confirmed plan change invalidates the old proof and prepares the new plan. Unverified cached preferences cannot admit a new paid session.

A disconnected active session can outlast Firestore's 45-second screen-slot reclaim interval. This is the deliberate tradeoff required to keep network interruption from stopping a verified viewer: strict concurrency during an outage would require pausing that viewer. Online transactions still enforce admission and reject unavailable screen slots; reconnect refreshes in the background.

Playback source order is:

1. The cookie-free NewTV API, using an exact verified provider title/episode identity. API-base discovery is cached for 24 hours. The optional API probe has at most four seconds and checks the returned master, advertised URI syntax and representative audio/video/subtitle renditions. It retains the master for adaptive playback and alternate tracks.
2. The provider's direct public HLS endpoint, attempted without cookies, fabricated tokens or an authentication workaround. This optional probe has at most two seconds.
3. The existing issued-playlist resolver, retaining its prior behavior.

The optional probes share the resolution deadline and stop consuming time when only the existing route's 18-second reserve remains. A placeholder clip returned with HTTP 200 to the unsigned probe rejects that probe only; it cannot establish a provider-wide cooldown or prevent the issued route. Real HTTP 429, explicit limit errors and a waiting clip with Retry-After still stop same-provider requests. The issued route continues to reject known waiting clips as before.

The guide's fake-CAPTCHA, crafted-token and universal-token bypass instructions are not part of this implementation. No third-party access control or geographic restriction is bypassed.

Exact season/episode selection remains required; an unavailable mapping does not become a guessed content ID. Cold episode discovery can still depend on the existing public provider metadata. A provider cooldown can prevent that prerequisite when no exact identity has previously been verified.

A NewTV player API rejection (HTTP 403/404) skips that optional service for 60 seconds using a monotonic, in-memory deadline, then permits an automatic retry. This is service availability handling, not a provider-wide rate limit. Repeated titles continue through the fallback during this window; a CDN rejection does not disable the API.

NewTV and the existing provider have independent rate-limit state. Media loading carries its source identity into the guard so one route's limit does not block a healthy alternative. A provider's Retry-After blocks further requests to that provider, and repeated user taps share in-flight resolution. Explicit source invalidation clears both the wrapper cache and the lower resolved-URL cache while retaining exact identity metadata. A real nine-minute video is no longer classified as rate limited solely by duration.

Validation includes Android builds, unit/Robolectric/Compose tests and lint for each app, with regression fixtures for startup admission, transient versus authoritative failures, account/expiry isolation, route order, malformed manifests, safe URLs, cancellation, retry budgets, cached discovery, provider backoff and failed-URL eviction.

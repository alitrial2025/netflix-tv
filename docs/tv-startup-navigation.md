# TV startup, profile editing and navigation

The splash now waits before the N zoom/burst. One 45-second preparation budget covers local account/profile state, catalogue core rows, a bounded artwork window and native stream-session warming in parallel. Existing paid TV accounts can warm before choosing a profile; this does not select a profile or bypass its PIN. Guests and inactive/Mobile-only accounts do not run paid warming. Cached sessions can finish immediately. Offline entry uses local state without waiting for network work. Provider failures and the overall deadline allow entry, with the existing foreground playback recovery retained.

Discovery is allowed during the preparation phase. When the phase ends, optional catalogue publication and maintenance return to the existing first-Home-frame and input-idle gate. Native warming does not start Chromium on Home. Artwork preparation covers at most one hero and six posters, rather than decoding every row. The 45 seconds bound preparation; the existing logo animation follows it and is not an artificial fixed 45-second wait.

Profile picker OK/Enter activation is handled once by the TV Surface. The previous custom KeyDown handler plus Surface activation could navigate twice. Profile Edit navigation also checks that the picker is still current and uses launchSingleTop. Done/Delete/language Done labels are measured in centered 48dp boxes, and menu icon/label groups are centered.

Home retains only its first adult Home rail across header, billboard and category focus. Returning to the header no longer discards that rail immediately before the next Down press. The billboard story fades instead of expanding/shrinking during the vertical spring, avoiding repeated text measurement. Horizontal/vertical spring stiffness and D-pad repeat pacing remain unchanged. Tab reveals wait for first layout; Search artwork waits for the reveal and quiet input, with stable recommendation order to reuse cached posters.

Debug RuntimeTiming markers record splash preparation outcome and first tab layout. Regression tests use virtual-time startup deadlines/cancellation, production profile Surface key dispatch, native Compose button bounds/actions, existing D-pad dispatch/row visibility and motion checks. These are not physical-device frame-time benchmarks; Android TV emulator/device playback and jank profiling remain separate runtime validation.
